# lazywinadmin.com blog MCP server

A small **read-only** remote [Model Context Protocol](https://modelcontextprotocol.io) server that lets AI assistants search and read the posts on lazywinadmin.com. It runs as a **Cloudflare Worker** and uses the **Streamable HTTP** transport in stateless JSON mode (`@modelcontextprotocol/sdk`).

```
AI client ──POST /mcp──▶ Worker (this folder) ──GET (cached)──▶ https://lazywinadmin.com/api/posts.json
                                                               (generated by Jekyll: /api/posts.json)
```

No secrets, no database, no write operations. All data comes from the public JSON index that Jekyll builds (`/api/posts.json` in the repo root). This folder is excluded from the Jekyll build (`exclude: - mcp` in `_config.yml`).

## Tools

| Tool | Arguments | Returns |
|---|---|---|
| `search_posts` | `query` (string), `limit` (1–50, default 10) | Keyword/fuzzy matches over title, tags, TL;DR and excerpt, ranked |
| `get_post` | `url_or_slug` (absolute URL, `/2013/10/x.html` path, or slug) | Full plain-text content with title/URL/date/updated/tags/TL;DR header |
| `list_recent_posts` | `n` (1–50, default 10) | Newest posts first |
| `list_tags` | – | Tags with post counts |

All tools are annotated `readOnlyHint: true`.

## Local development

```bash
cd mcp
npm install

# 1) Fast smoke test in plain Node against a locally built index
bundle exec jekyll build            # from the repo root -> _site/api/posts.json
INDEX_FILE=../_site/api/posts.json npm test

# 2) Real Workers runtime
#    Point the Worker at a local copy of the index (file is git-ignored):
(cd ../_site && python3 -m http.server 8799 --bind 127.0.0.1) &
echo 'INDEX_URL="http://127.0.0.1:8799/api/posts.json"' > .dev.vars
npx wrangler dev            # http://localhost:8787/mcp

# 3) Inspect with the official MCP Inspector
npx @modelcontextprotocol/inspector --cli http://localhost:8787/mcp --transport http --method tools/list
npx @modelcontextprotocol/inspector                       # UI: choose "Streamable HTTP", URL http://localhost:8787/mcp
```

Without `.dev.vars`, `wrangler dev` uses the live `https://lazywinadmin.com/api/posts.json` (it only exists after this PR is merged and deployed).

## Deploy (needs your Cloudflare login)

1. Merge the PR and wait for pages.yml so `https://lazywinadmin.com/api/posts.json` returns 200.
2. Then:
   ```bash
   cd mcp
   npm install
   npx wrangler login      # opens the browser; sign in to the Cloudflare account that owns lazywinadmin.com
   npx wrangler deploy     # publishes to https://lazywinadmin-blog-mcp.<your-subdomain>.workers.dev
   ```
3. Optional custom domain: uncomment the `routes` line in `wrangler.toml`
   (`mcp.lazywinadmin.com`, `custom_domain = true`) and run `npx wrangler deploy` again. Wrangler creates the DNS record and certificate, since the zone is already on Cloudflare.
4. Check it: `npx @modelcontextprotocol/inspector --cli https://mcp.lazywinadmin.com/mcp --transport http --method tools/list`

The endpoint is `https://<host>/mcp`. `GET /` returns a short text banner.

## Connect a client

Use `https://mcp.lazywinadmin.com/mcp`, or the workers.dev URL, as the server URL.

- **Claude (claude.ai / Desktop):** Settings → Connectors → *Add custom connector* → paste the URL. No auth is needed.
- **Claude Code:** `claude mcp add --transport http lazywinadmin https://mcp.lazywinadmin.com/mcp`
- **VS Code (GitHub Copilot agent mode):** `.vscode/mcp.json`
  ```json
  { "servers": { "lazywinadmin": { "type": "http", "url": "https://mcp.lazywinadmin.com/mcp" } } }
  ```
- **Cursor:** `~/.cursor/mcp.json` (or `.cursor/mcp.json` in a project)
  ```json
  { "mcpServers": { "lazywinadmin": { "url": "https://mcp.lazywinadmin.com/mcp" } } }
  ```
- **Windsurf / other clients with Streamable HTTP:** add a server with the same URL.
- **stdio-only clients:** bridge with `npx mcp-remote https://mcp.lazywinadmin.com/mcp`.

## Caching and rate limiting

- **Index caching:** each Worker isolate keeps the parsed index in memory for `INDEX_TTL` seconds (default 600). The upstream fetch also uses `cf.cacheTtl`, so most requests are served from Cloudflare's edge cache rather than GitHub Pages. If the upstream fetch fails, a stale in-memory copy is served. New posts appear within about 10 minutes of a site deploy.
- **Request limits:** request bodies over 64 KB are rejected, and `limit`/`n` are capped at 50 by the tool schemas.
- **Rate limiting (recommended once public):** pick one of these.
  - A Cloudflare dashboard **WAF rate limiting rule** on `mcp.lazywinadmin.com/mcp`, e.g. 60 requests per minute per IP. This needs no code.
  - The Workers **Rate Limiting binding**: add this to `wrangler.toml`, then call `env.RATE_LIMITER.limit({ key: ip })` in `handle()` before connecting the server.
    ```toml
    [[ratelimits]]
    name = "RATE_LIMITER"
    namespace_id = "1001"
    simple = { limit = 60, period = 60 }
    ```
- **Cost:** the Workers free plan (100k requests/day) is plenty for this.

## Security notes

- Read-only: the tools only read the public index. There are no bindings, KV, secrets or tokens, so there's nothing to leak.
- Stateless: no `Mcp-Session-Id`, and GET/SSE streams are not offered (405). CORS is open because the data is public.
- To add authentication later, put Cloudflare Access in front of the route, or switch to the `agents` SDK's `McpAgent` + OAuth provider.
